# Web 控制台后续计划

更新时间：2026-07-31。开发分支：`add-web`。

## 已完成：第一期，本地日终闭环

- `quant-web` 默认仅监听 `127.0.0.1`。
- 页面可启动日终任务，并以单 worker 串行刷新日线、涨跌停价、资金流、指数、板块快照和交易信号。
- 任务状态、执行记录和结构化日报保存到独立的 `data/meta/web.db`。
- 页面展示仓位策略、正式买入、观察机会、持仓、新闻、板块和告警。
- 日终工作流直接调用内部 Go 模块，不通过页面拼接或执行 CLI 命令。
- Web 数据库使用版本化迁移；服务重启会恢复排队任务并终结遗留运行任务。
- 任务原子入队，worker 会重试数据库瞬时错误并捕获任务执行 panic。

## 下一步：第二期，持仓与报告中心

目标：让页面能够安全地维护交易流水，并把每次分析结果与当时持仓关联起来。

1. 确定交易流水的唯一事实来源。
   - [x] 将 SQLite 中的交易流水作为 Web 的唯一可写来源。
   - [x] 提供 `portfolio.yaml` 显式导入和 YAML 手动导出，避免既有数据丢失。
   - [x] 不允许 Web 与 YAML 双向自动写入，防止两个来源产生冲突。
   - [x] 导入及新增交易执行字段校验、历史超卖校验并写入审计记录。
2. 实现持仓页面。
   - [x] 查看当前持仓、成本、最近日报价格、浮盈亏和已平仓明细。
   - [x] 新增买入、卖出、修改备注和撤销错误记录。
   - [x] 所有修改记录创建时间、来源和操作前后值，便于审计与回滚。
   - [x] 页面写操作增加 CSRF 校验，修改和撤销使用乐观锁防止覆盖。
3. 实现报告中心。
   - 按日期、任务状态和交易日浏览历史日报。
   - 报告绑定其使用的数据日期、策略版本、持仓快照和任务日志。
   - 任务增加“日终分析”“月度价值筛选”“季度价值复核”三种明确类型；价值任务继续与日常交易任务隔离。
4. 增加本地定时任务设置。
   - 仅允许配置白名单任务和交易日时间窗口。
   - 定时器只入队，不绕过单 worker，也不直接并发写 Parquet。

验收标准：可在页面完整录入一笔买卖，持仓和日报随之可追溯；重启服务后任务、交易流水和报告仍可读取。

## 第三期：AI 报告分析与自由问答

目标：在服务端安全调用 DeepSeek 等 OpenAI 兼容模型，让 AI 解释数据，而非替用户交易。

1. 建立 AI 提供方模块。
   - 统一 OpenAI 兼容接口；DeepSeek 只是第一个 adapter。
   - API Key 仅从环境变量或受限配置读取，绝不发送给浏览器、不写入任务日志。
   - 记录模型名、请求时间、关联报告和消耗统计；敏感内容不完整落盘。
2. 提供两种会话模式。
   - 报告问答：用户在某一份日报或价值报告内提问，服务端只注入该报告的结构化摘要。
   - 自由问答：不自动携带持仓、交易流水或 Token；用户必须主动选择要附带的报告上下文。
3. 固化 AI 输出边界。
   - 输出必须区分“原始数据”“模型推断”“数据不足”。
   - AI 不能修改持仓、执行任务、调用 Shell 或发起交易。
   - AI 结论不能覆盖仓位策略中的空仓/观望约束；页面需要显示风险提示与数据日期。
4. 提供日报分析提示词模板。
   - 复用 `docs/prompts.md` 的日终、月度价值和季度复核口径。
   - 将报告转换为紧凑的、带版本号的 AI 输入，避免把完整 Parquet 或无关个人信息发送给模型。

验收标准：可对指定历史日报提出问题并保存答案；浏览器、数据库和日志中均不出现 API Key；自由问答默认没有投资组合上下文。

## 第四期：主机部署与安全上线

目标：不使用 Docker，采用直接主机部署，但达到单用户互联网访问所需的基本安全标准。

1. 部署方式。
   - Go 二进制由 `systemd` 管理，使用专用低权限用户运行。
   - 配置和密钥放在仅该用户可读的环境文件中。
   - Caddy 负责 HTTPS、证书续期和反向代理；应用仍只监听 `127.0.0.1`。
2. 访问控制。
   - 上线前增加登录认证、强密码/二次验证、会话过期、CSRF 防护和登录审计。
   - 防火墙只开放 SSH、HTTP/HTTPS；SQLite、Parquet、任务端点和模型密钥不暴露到公网。
3. 数据保护与可恢复性。
   - 每日备份 `data/`、`web.db` 和交易流水导出；定期演练恢复。
   - 保留任务和报告的版本，禁止后台清理未备份的交易记录。
   - 监控磁盘空间、任务失败、行情数据过期和模型调用异常。
4. 合规与域名。
   - 使用域名与 DNS；配置证书自动续期。
   - 若在中国大陆面向公网提供服务，先确认备案和云厂商要求。

验收标准：重启主机后服务和定时任务自动恢复；HTTPS、认证、备份恢复和密钥隔离均经过实际演练。

## 实施顺序与不变约束

实施顺序固定为：第二期持仓/报告 → 第三期 AI → 第四期公网部署。每期完成后再决定下一期范围，不一次性引入复杂框架或微服务。

- 原始市场数据继续使用 Parquet；应用状态、任务、报告索引和交易流水使用 SQLite。
- 日常信号与慢频价值投资任务继续隔离；PE/PB/ROE 不进入日常短中线策略。
- 日终任务始终串行，盘中实时行情只在 A 股连续竞价时段拉取。
- 空仓或观望时，正式买入必须为空；观察机会只能标记为跟踪或等待确认。
- 不使用 Docker；不在未补齐认证和访问防护前开放公网。
