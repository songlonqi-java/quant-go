# 本地 Web 控制台（第一期）

第一期目标是把“运行一次日终流程 → 查看结构化报告”做成可审计的本地闭环，而不是把命令行简单套一层页面。

## 启动

```bash
go build -o quant-web ./cmd/quant-web/
./quant-web -c config.yaml
```

默认访问地址为 `http://127.0.0.1:8080`。服务只绑定回环地址，因此只能从运行程序的本机访问；浏览器不会获得 Tushare Token，也不会直接请求行情或 AI 服务。

可选参数：

| 参数 | 说明 |
|------|------|
| `-c`, `--config` | 配置文件，默认 `config.yaml` |
| `--addr` | 监听地址，默认 `127.0.0.1:8080` |
| `--db` | 任务数据库，默认 `<data.meta_dir>/web.db` |
| `--portfolio` | 持仓流水，默认 `portfolio.yaml` |

健康检查为 `GET /healthz`，返回 `ok`。

## Web 交易流水

Web 使用 `web.db` 中的 SQLite 交易流水作为唯一持仓数据来源。CLI 仍可继续读取 `portfolio.yaml`，但 Web 不会在后台自动同步 YAML，避免两个来源相互覆盖。

首次升级后，可在首页点击“从 portfolio.yaml 导入”。导入会先校验日期、股票代码、买卖方向、股数、价格以及历史任一时点是否超卖，然后在一个事务中写入交易和审计记录。只有 SQLite 流水为空时允许导入，同一个 YAML 文件不会重复导入。首页的“导出 YAML”可随时下载当前有效流水，作为备份或供 CLI 使用。

数据库迁移会自动创建 `portfolio_transactions`、`portfolio_audit_logs` 和 `portfolio_imports`，不需要安装新的服务。持仓页面支持逐笔录入买卖、查看当前持仓与已平仓明细、修改备注和撤销错误记录。撤销采用可审计的作废状态，不会物理删除；如果撤销一笔买入会使后续卖出超出持仓，操作将被拒绝。

所有页面写操作均校验 CSRF 令牌。交易修改使用版本号进行乐观锁检查；如果另一个页面已经修改了同一记录，旧页面提交会失败并要求刷新。持仓中的最近价格来自最近一次成功日报，并显示对应交易日；尚无日报价格时不会伪造实时盈亏。

## 日终任务

点击“运行日常日终任务”后，后台按顺序执行：

1. 拉取当日日线；若 Tushare 还未发布，记录为跳过并使用本地最近交易日。
2. 拉取当日涨跌停价、资金流向和指数数据。
3. 用本地最新日线构建板块快照。
4. 运行既有的 `signalworkflow.Run`，在连续竞价时段按既有规则获取实时行情。
5. 将市场、仓位策略、正式买入、观察机会、持仓、新闻、板块和告警写为结构化日报。

任务状态、进度事件和日报存入独立的 SQLite 数据库 `web.db`。市场数据仍保留在原有 Parquet 目录；Web 数据库不替代行情存储，也不混入已有 `quant.db`。

同一时间只允许一个日终任务处于排队或运行状态。这样避免多个任务同时合并写入同一份 Parquet 文件。页面会自动刷新显示进度。

任务数据库使用内置 SQLite，不需要安装或启动额外的数据库服务。程序启动时会自动执行带版本号的数据库迁移，已有任务和报告会保留。建议升级二进制前备份 `web.db`。

如果服务在任务执行过程中退出，下一次启动会把遗留的运行中任务标记为失败并记录“服务重启，任务已中断”；尚未开始的排队任务会由新 worker 继续执行。任务创建使用原子入队，同一时间不会创建多个行情写入任务。worker 会重试瞬时数据库错误，并将任务执行 panic 转换为可查看的失败记录。

## 慢频数据与价值任务

首页提供“准备慢频数据”“月度价值筛选”和“季度价值复核”。准备任务刷新本地最新交易日的 `daily_basic` 并重建行业估值快照；财务指标仍通过完整的 `fetch-financials` 流程更新，避免增量操作覆盖历史财务文件。月度和季度任务运行前都会检查估值、财务和行业数据是否就绪，三类数据对最新股票集合的覆盖率均须达到 95%。

价值任务使用本地已经准备好的日线、`daily_basic`、财务指标和行业估值快照。月度任务运行前应显式刷新对应交易日估值并构建板块快照；季度任务还要求已经存在月度价值快照。数据不完整时任务会失败并保留错误日志，不会降低筛选门槛或改用过期口径。

## 报告中心

`GET /reports` 提供独立报告中心，可按报告类型、交易日和任务状态筛选。只有日终、月度价值和季度价值等分析结果进入报告中心；备份和数据准备产物留在对应任务详情，避免被误解为投资分析报告。任务记录仍保存执行状态与完整日志；报告记录保存结构化分析结果，两者通过任务编号关联。

每份新报告会记录以下可追溯信息：

- 报告 schema 版本和生成时间。
- 实际交易日及数据版本。
- 构建代码版本；本地开发构建无法取得 Git revision 时显示 `development`。
- 按策略名称集合生成的策略版本摘要。
- 任务开始分析时读取的完整有效交易流水快照及其 SHA-256 摘要。

后续修改或撤销交易不会改变历史报告中的持仓快照。升级前已经存在于 `web_tasks.report_json` 的旧日报会自动进入报告索引，但由于当时没有保存流水快照，详情页会明确显示“旧报告没有持仓流水快照”。

## 本地定时任务

`GET /schedules` 可配置日终分析、慢频数据准备、月度/季度价值任务和本地备份。默认全部关闭，启用后仍只由现有单 worker 串行执行。

- 所有定时规则固定使用 `Asia/Shanghai`。
- 只在本地 `trade_cal.parquet` 明确包含的 A 股交易日入队；交易日历缺失或过期时不会猜测执行。
- 日终任务按交易日每天最多入队一次。
- 月度价值任务在设置日及其后的第一个可运行交易日入队，每月最多一次。
- 季度价值任务默认在 1、4、7、10 月运行，可修改月份列表，每月最多一次。
- 服务关闭期间不会执行任务；重启后如果当前周期已经到达设置时间且尚未入队，会补充入队一次。任务创建和周期标记在同一个 SQLite 事务中完成；同类型手工任务占用队列时不会提前消耗定时周期。
- 定时器只负责入队，不直接调用行情写入、价值筛选或 Shell。

定时设置、启用状态和最近入队周期保存在 `web.db`，重启后仍会保留。

## 监控、备份与 AI

`GET /monitoring` 展示交易日历最新日期、磁盘可用空间、近 7 日失败任务、慢频数据覆盖和最近备份。任何检查失败都会显示“未知”和具体错误，不会用 0 或“无”伪装成正常结果。备份任务通过 SQLite `VACUUM INTO` 创建一致性快照，并将 `web.db`、持仓 YAML 与原始市场数据打包到 `backup.dir`；默认目录为 `<data.meta_dir>/backups`，默认保留 14 份。`backup.dir` 不得与 `data.raw_dir` 相同或互相包含，服务启动和执行备份时都会拒绝危险配置。

AI 问答只在指定历史报告内工作，只发送该报告的紧凑结构化摘要，不发送 API Key，也不能修改持仓、执行任务或交易。回答必须明确区分“报告原始数据”“模型推断”“数据不足”和“风险提示”；不满足结构要求的回答不会保存。页面显示报告数据日期、风险边界和模型 token 用量。DeepSeek 使用 OpenAI 兼容接口，配置示例：

```yaml
ai:
  enabled: true
  base_url: "https://api.deepseek.com"
  api_key_env: "QUANT_AI_API_KEY"
  model: "deepseek-chat"
  timeout_sec: 60
backup:
  dir: "./data/meta/backups"
  retention: 14
```

建议只通过 `QUANT_AI_API_KEY` 环境变量提供 Key；也可改变 `api_key_env` 指向自定义环境变量。`QUANT_AI_BASE_URL` 和 `QUANT_AI_MODEL` 可覆盖文件配置。回答与模型名会保存到 `web.db`，Key 不会落库。

## 当前范围

当前已包含：本地任务入口、单 worker 串行执行、任务历史、进度事件、结构化分析报告、SQLite 持仓流水、慢频价值任务、本地定时、监控、备份和指定报告 AI 问答。

尚未包含：用户认证、自由问答、HTTPS 与外网主机发布。公开部署继续放在后期；在认证和访问防护完成前，不要把 `--addr` 改为公网地址。
